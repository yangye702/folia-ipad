# Phase 1 / P0 第二轮：规模化匹配可靠性

基线：`3479a385129d3d7f13df7f94cc13984a60a5cc5a`。同一 `feat/ipad-lyrics-visual-touch-v1`、Draft PR #3、同一 Preview 来源。没有全量同步上游或任何数据库版本/音频/播放状态机变更。

## 真实证据与仍未知的原因

- **iPad 已证实**：部分封面补全成功；36首文件夹剩余项目曾需约20轮人工重启；诊断出现 `NETEASE_API_BASE_MISSING`、QQ HTTP200/request.code2001、酷狗network及partial-search-failure。
- **源码已证实**：旧批量只有两歌曲并发/来源串行，没有批次来源健康状态、请求去重、退避或自动恢复。每首都会重复遇到缺后端，临时失败只记为最终失败。这解释“需要人工重新启动”这一软件机制，不能证明20轮失败全由同一外部原因造成。
- **QQ 定位**：匿名 POST `/api/lyric-proxy` → `u.y.qq.com/cgi-bin/musicu.fcg` → `music.search.SearchCgiService.DoSearchForQQMusicLite`；2001在 `request.code`，HTTP200只证明收到了响应。以前真机已有“同一歌简体拒绝、繁体成功”的证据。不是封禁、限流或Safari故障的证明；精确上游触发条件仍未知。
- **酷狗定位**：无已登录会话时，原签名匿名搜索经同一Vercel代理到 `complexsearch.kugou.com/v2/search/song`；有会话则沿用配置的KuGouMusicApi路径。本轮不改参数、签名、账户和响应字段映射。旧network日志不含失败跳点，不能追溯断言浏览器、代理或上游哪层出错。
- **云端限制**：本环境受控出口仅许可部分域名，Preview探测为CONNECT403/HTTP000，未到达应用；未取得本轮真实QQ/酷狗响应。没有借此推断iPad平台失败，也没有高频探测或修改网络/Production配置。

## 网易云为何不可用

`src/services/onlineMusic/netease/netease.ts:getConfiguredApiBase/getApiBase` 在Web构建缺少 `VITE_NETEASE_API_BASE` 时本地抛错，还没发送网易云网络请求。此变量由Vite构建期注入；`.env.example`只是模板，不会自动变成Vercel项目变量。

当前仓库的 `vercel.json`/`api-ts/` 只提供已有QQ/歌词代理等函数，没有兼容 `/cloudsearch`、`/register/anonimous`、歌词接口的网易云API后端。Electron使用内嵌服务，Docker方案在 `deploy/docker/images/netease-api.Dockerfile` 中运行钉死的 `@neteasecloudmusicapienhanced/api@4.41.1`；Vercel前端构建不会启动该容器。这是原Web部署的后端依赖，不是iPad独有问题。尚未读取Vercel环境设置，不能断言变量是未填、作用域不对还是另一次构建缺失。

|可选恢复方式|架构/成本|边界与决定|
|---|---|---|
|复用用户已有可信API实例|仅为现有Preview构建配置API地址；额外基础设施可为0|需先证实实例可访问、HTTPS/CORS及接口兼容。本轮没有获知可用实例，不填随机公共服务或localhost|
|复用仓库Docker后端|常驻主机+API容器+HTTPS；已有主机可能无新增费用，否则费用及运维待选服务报价|需要额外常驻基础设施，不符合当前无服务器目标；未创建/部署|
|在同一Vercel项目另做后端适配|需单独核查第三方API依赖、冷启动、执行时限及Hobby额度；不能承诺一直免费稳定|属于额外后端实施方案，不在本轮悄悄增加，待独立审查与确认|

本轮无需用户增加配置即可使用其他现有来源，并明确显示网易云本批不可用。若要恢复网易云，仍需已验证的兼容后端和相应Preview构建配置。第三方API包装库不是网易云官方公共托管服务。

## 本轮代码与策略

|缺陷/遗漏|实施|代码|
|---|---|---|
|逐首重复请求不可用来源|每批次记住未配置、明确认证要求、HTTP401/403；后续直接跳过并给出来源提示，不伪装为空结果|`matchingSearchSession.ts`、`FolderAutoMatchEditor.tsx`|
|只限并发，无恢复/去重|每来源一个真实请求槽、开始间隔至少400ms；相同搜索在途合并及有界内存缓存；最多两歌曲并发|`matchingSearchSession.ts`、`lyricMatchSources.ts`|
|把排队等待算作网络超时，旧请求可与重试重叠|请求开始才计算15秒预算；自动歌词搜索保留原3.5秒请求预算；排队另限30秒并标source-busy。不能中止的旧请求真实结束前不释放来源槽；超时的排队项退休，不会稍后补发|同上、`autoMatchBestLyric.ts`|
|临时故障需人工重启|网络、超时、429/5xx进入1/2/4…秒、有上限的来源退避；尊重Retry-After。只对未完成项增加最多两轮自动恢复，读取最新已提交记录。等待超过本轮60秒预算时保留未完成状态，不缩短上游等待要求|`matchingSearchSession.ts`、`localSongMetadataMatchService.ts`|
|长批次缓存过期后重发同一拒绝|本批次有界记住不宜重试的查询；QQ2001不作为全平台失效，不增加同一关键词的快速重试。既有最多6种去重的简繁/标题变体保留|同上、`qqLyricProvider.ts`|
|成功搜索也可能过早停止|普通自动信息搜索在成功但不足时，有限去掉专辑/歌手约束；已可靠但缺图则继续其他来源。QQ自动资料/封面匹配可在首组结果不满足准入时继续原有有限变体；人工搜索仍原样返回首组结果；显式手动重试不复用先前拒绝，临时故障按退避后重新请求|`onlineMetadataSearchService.ts`、`qqLyricMatchAccess.ts`|
|partial-search-failure缺失跳点|代理加安全阶段/上游HTTP/Retry-After响应头；客户端区分未收响应、代理连接/超时/解析、上游HTTP及业务拒绝。不向客户端返回原异常文本|`api-ts/lyric-proxy.ts`、生成JS、`lyricProxy.ts`、`kugouTransport.ts`、`qqLyricSearchStatus.ts`|
|60条环形日志不足以诊断千首任务|保留60条事件，另保存最后批次聚合：每来源逻辑搜索数、成功/失败、缓存命中、跳过、恢复、最后安全错误，最终状态与耗时。诊断仍仅URL明确开启时在内存保留|`matchingDiagnostics.ts`、`MatchingDiagnostics.tsx`|

没有降低上一轮标题、歌手、专辑、版本及时长准入。没有针对歌曲/歌手硬编码。元数据成功而封面未完成可独立续跑；已有歌词、人工信息、纯音乐/noAutoMatch、嵌入封面、旧封面及事务取消保护沿用。恢复读取原表，不执行读时迁移、重建或音乐数据清理。默认歌词检索缓存区分账户身份，原账号凭据不进入诊断。

缓存上限：成功/短期结果500条，本批拒绝2000条；不会无限增长。此任务不是常驻后台任务系统：关闭/取消后停止新应用，底层不能中断的请求可能仍结束；再次打开从已有已保存结果识别剩余项，不要求重导入。

## 规模实验：全部为受控模拟

运行真实批量编排、搜索回退、准入与取消代码；平台响应受控，保存边界为隔离内存夹具，**下表保存率不是OPFS实测或真实在线成功率**。所有场景错误匹配为0。100%只针对设定的合成歌曲；mixed故意加入10%错误歌手，正确保留为low-confidence。refused故意持续拒绝/断网，必须维持失败，不制造成功。

同一脚本另在基线归档源码运行对照。每次模拟响应耗时10ms，outage中的QQ/酷狗在起始1500ms不可用；missing-backend是本地配置错误。dedup每两条合成记录共享同一检索身份。cancel-resume在5条终态后取消、等20秒确认无延迟写入，再续跑未完成项。

**调用数是匹配provider搜索调用**（含本地配置拒绝），不是HTTP请求数；QQ一次调用可包含多个原有RPC变体。重复查询包含有意的有限恢复探测。耗时使用虚拟时钟，包含400ms节奏/退避，不是iPad测速。所有来源正常时新逻辑会更慢，目的是控制请求节奏；不能把减少请求等同于测得的平台限流修复。

## 验证、交付与真机界限

最终类型检查、构建、全量单测、浏览器和部署状态见本次交付记录。浏览器新增场景使用真实IndexedDB/OPFS及图片解码：8首歌曲、网易云一次403后批次跳过、QQ前两次模拟代理502后恢复；检查旧歌词/人工资料及刷新封面恢复。平台仍使用Mock。之前本地MP3双曲导入播放和手动歌词拒绝诊断回归继续运行。

诊断链接沿用原Preview，加 `?matchDebug=1&qqLyricDebug=1`。整理歌曲信息中展开“在线匹配诊断”→“复制诊断”；受限时点击文本框全选，再系统拷贝。QQ歌词入口保留原诊断。删除参数即可隐藏，不上传日志，不记录音频、Cookie/Token或原始响应。

**iPad只需一次集中验收**：在原36首文件夹，仅选择仍缺图/未完成项，保持网页前台运行一次，等待有限自动恢复结束；复制本批汇总（即使仍有少数失败），刷新检查新成果保留、已有正确封面不变。持续失败项凭新阶段信息判断是否需后端/外部资源，不再要求人工连续启动20轮。不重测已验收触屏切歌、M3U、基础播放和普通歌词同步。P0与整个Phase1最终是否通过仍由用户真机确认。
