# QQ 歌词搜索：错误分类与真机取证

## 已证实的问题与本次边界

本次复用本地 `f1cef8c0` 的报告、差异和 88 项测试结果，没有重复被云环境阻断的真实关键词探测。旧行为中，请求失败、QQ 拒绝、响应结构缺失均可能变成 `[]`，使匹配窗口保持 `searchError=false`。这足以证明错误显示问题，但不足以判断用户《幸福不远》那次请求的真实结果。

本次保持匿名 RPC、请求参数、POST 路由和歌词获取逻辑不变，没有引入关键词回退、认证路径替换、新平台、付费 API 或自动重试。未改音乐文件、歌词数据、曲库、播放队列、锁屏或触屏切歌。

## 已实施

- `searchQQLyrics` 不再吞掉搜索异常；匹配窗口沿用原错误状态，并增加 QQ 专属错误类别文案。
- 搜索响应区分 `network`（未取得 HTTP 响应）、`http`（客户端收到非成功 HTTP）、`upstream`（QQ 响应码非零）、`invalid-response`（JSON/信封/歌曲列表结构异常）。只有有效成功信封及合法空列表表示零匹配。空输入仍不发请求。
- 搜索成功码、歌曲列表结构和基本条目结构会校验。歌词下载仍沿用原 `requestQQ` 处理分支；没有改歌词解析或数据。
- 普通 QQ 搜歌仍沿用现有“有会话走后端、必要时回退匿名”的架构；没有把歌词搜索换成该路径。现有元数据匹配的 QQ 失败捕获及后续回退路径保留，相关测试覆盖该调用方。
- 只在 `qqLyricDebug=1` 且处于 QQ 歌词标签时显示诊断面板。只记录最近 30 次 QQ 歌词搜索，保存在页面内存中，刷新即清空。不写 sessionStorage、localStorage、IndexedDB 或 OPFS，不上传。
- 诊断只含输入关键词（最多 60 字）、时间、请求序号、路由、客户端 HTTP 状态、两层码、结构摘要、列表数量和结果分类；不含 Cookie、令牌、请求头、完整请求正文、原始响应、音频或音乐文件路径。普通在线搜歌不会进入这个歌词诊断列表。

HTTP 是 Safari 收到的代理响应状态，并不单独证明 QQ 接受了请求。`responseKind: unknown` 表示未取得可识别的 QQ 双层码，不能把代理自身的错误当作 QQ 返回码。缺失信息是 null，不冒充 0；被拒响应里即使有列表，观察到的列表长度也不等于成功匹配。

## 通过现有 Vercel Preview 验证

本地改动只有在推送 `feat/ipad-lyrics-visual-touch-v1` 并由现有项目生成新的 Preview 后才会上线。推送会同时带上尚未推送的 f1cef8c0 报告和特征测试。不会合并 Draft PR，也不发布 Production。

部署完成、确认 Preview 对应本次新提交后，在 iPad Safari 打开：

https://folia-ipad-preview-git-feat-ipad-lyr-3ee6e8-yangye702s-projects.vercel.app/?qqLyricDebug=1

1. 使用现有本地歌曲，打开歌词匹配，切换 QQ 标签。不必重新导入 MP3，不要保存或应用歌词，仅搜索和查看。
2. 展开搜索框下的「QQ 歌词搜索诊断」。现有元数据可能含专辑，先检查实际记录的 query。
3. 手动依次输入并搜索：`幸福不远 - 郭书瑶`、`幸福不远`、`幸福不遠`。一次搜索结束后再做下一次；没有自动回退。
4. 每次查看 `httpStatus`、`topCode`、`requestCode`、`responseKind`、`listShape`、`resultCount`、`outcome`。失败时界面不应再显示普通“未找到结果”。
5. 点击「复制诊断」。剪贴板权限不允许时，点击「选择诊断文本」，长按文本使用 iPad 的「拷贝」。不需要键盘、Mac 或开发者工具。
6. 复制后关闭匹配窗口；移除 `qqLyricDebug` 参数并刷新可退出调试并清空内存诊断。不要清除网站数据、重导音乐或改动任何已有歌词。

只有在完整关键词请求成功（HTTP 成功、QQ 两层码均为 0、结构有效）却为零，而仅歌名确有结果时，才有依据讨论歌名回退。出现网络/HTTP/上游拒绝时，不应改关键词掩盖失败。

## 云端与真机边界

浏览器回归使用实际匹配窗口、搜索 hook 和 QQ provider，仅控制上游响应；没有导入音乐或写入用户曲库。它验证错误文案、真实零结果、三组关键词各一次请求，以及触屏选择诊断文本。受控响应不是 QQ 的真实歌曲搜索结果。

上一轮真实 QQ 及 Preview 请求均在云环境 CONNECT 阶段被拒，本轮未重复这些无变化的网络检查。现有 GitHub 网页可用于核对分支和 Preview 部署状态，但这不能代替实际 iPad 对 QQ 的请求证据。尚待真机确认 Safari 请求结果、真实 QQ 双层码/数量、剪贴板权限及最终歌曲可匹配性。没有这些数据前不判断本曲是否需要繁简转换、歌名回退或其他修复。
